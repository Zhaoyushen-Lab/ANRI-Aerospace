# ANRI / AI4S / AI4E 日报模板

> 复制此文件为 `Research_Log/<YYYY-MM-DD>_ANRI_Daily.md` 后填写。
> **不要改动章节编号与顺序**——跨日对比依赖固定格式。
> 涉及判断的字段必须能追溯到证据；凡不是"读文件 / 跑命令拿到的结果"，
> 一律写进 §4.4 而不是 §1–§3。

- 日期：`YYYY-MM-DD`
- 口径版本：`v1`（首次发布于 2026-10-11；仅当评分方法本身变更时才升版）
- 状态快照：`Research_Log/<YYYY-MM-DD>_ANRI_State.json`（由 `scripts/collect_state.py` 生成）
- 上一份日报：`Research_Log/<上一日期>_ANRI_Daily.md`

生成当天快照：

```powershell
py -3 .\scripts\collect_state.py --out "Research_Log\<YYYY-MM-DD>_ANRI_State.json"
```

**推荐流程（自动化 §0 与 §4.5/§6）**：

```powershell
# 1. 采集状态（也可用 --no-suite 跳过慢套件）
py -3 .\scripts\collect_state.py --out "Research_Log\<YYYY-MM-DD>_ANRI_State.json"

# 2. 生成骨架：自动填入 §0（Δ 表 / 触发条件 / 趋势），其余章节留空
py -3 .\scripts\new_daily_report.py --date <YYYY-MM-DD>

# 3. 只填需要判断的章节：§1、§2、§3、§4.2–§4.5、§5
```

`scripts/new_daily_report.py` 会拒绝覆盖已存在的日报（除非 `--force`）。
它填的是**机器可测量**的部分（§0），§4.5 的 Δ 与 §6 的触发条件检查也在其中，
因此这三个部分不允许手工誊写，以免与快照不一致。

**触发条件维护**：触发条件声明在 `scripts/compare_snapshots.py` 的 `TRIGGERS`
列表中（含 ID、阈值日期、承诺的因子调整）。新增触发条件必须同时改代码与该节，
否则不会被检查。
