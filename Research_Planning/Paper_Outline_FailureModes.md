# 方法论论文大纲：可投性评估与两周计划

> **本文档回答：能不能用现有材料做出一份可投的方法论论文？**
>
> - 日期：2026-10-20
> - 材料：92 个哈希注册产物、26 条失效模式、覆盖矩阵、敏感性分析方法
> - 结论：**可写，但有一个硬阻塞（文献获取）和三个必须预先承认的弱点**

---

## 1. 先说结论：这篇论文能投，但不是你以为的那种

### 1.1 不能写的东西

| 想法 | 为什么不行 |
|---|---|
| "我们建了一个能验证科研可复现性的系统" | 无外部用户、无独立评审、**两个研究问题都是 `unresolved`** |
| "用它得到了更好的科研结果" | 没有任何一条结论从 `unresolved` 变成 Accepted |
| "我们的门禁很严格" | 覆盖矩阵显示 **13/26 个扰动对门禁不可见** |

**任何以"成功"为主线的写法都会在审稿时被一句话击穿：
你的研究结论在哪里？**

### 1.2 能写的东西

> **我们按自己的验证协议做了一个真实的工程研究，然后系统记录了
> 这套协议在哪里失效——包括它自己报告过的三处"已修复"其实没有修完。**

这是**负结果 / 失效分析**，不是成功报告。它的价值在于：

- **绝大多数基础设施论文只报成功**，失效分析稀缺
- 26 条缺陷有**日期、根因、检测手段、以及"为什么检测没抓到"**
- 全部产物哈希冻结、可复现，审稿人能自己重算分类

---

## 2. 核心主张（一句话）

> **在工程域实例化一个研究对象验证协议时，失效集中在检测手段自身，
> 而不在被检测的对象上：本项目 26 条缺陷中，21 条是"检查器看不见"，
> 而非"数据错了"。**

**这个主张可证伪**：别人可以用同一分类法审自己的基础设施，看比例是否相似。

## 5. 结构（六节）

### §1 Introduction
- **问题**：AI 进入工程科研后，"这个结果可不可信"成为采购/审稿的实际问题
- **现有答案**：哈希冻结（完整性）+ 自动校验（若干不变量）
- **本文做了什么**：把这套东西用在一个真实工程问题上，记录了它在哪里断
- **贡献三条**（见 §5.1）
- **素材**：`README.md` 的 "Where the project actually is" 一节可直接改写

### §2 The protocol under test
- 研究对象结构（schema v0.2）、哈希注册、离线校验器、review gate
- 五层检测：校验器 / 基线校验 + 18 负例 / 12 对抗 / 13 篡改自测 / CI
- **关键**：把它当作**被测对象**，不是我们的成果
- **素材**：`Research_Objects/RO-CDFV-001-Ref-01B.json`、`scripts/*.py`

### §3 Method: how defects were found
- 缺陷来源：两轮修复周期 + 冷启动检查 + 逐列覆盖探针 + 敏感性分析
- **记录格式**：现象 / 根因 / 为何检测没抓到 / 修复 / 当前状态
- **素材**：`Reviews/ANRI_Failure_Mode_Report_v0.1.md`（已有 26 条，7 类）

### §4 The taxonomy (核心贡献)
七个类别：

| 类 | 名称 | 条数 |
|---|---|---:|
| A | 检查式子里写进了假设 | 2 |
| B | 修复只在测试它的环境里成立 | 2 |
| C | 度量在测别的东西 | 4 |
| D | 历史是可变的 | 3 |
| E | 生成器破坏自己的产物 | 2 |
| F | 基准/归一化错误 | 3 |
| G | 修复存在，但不在该在的地方 | 1 |

**三个最有说服力的实例**：
1. **F7 标记 `Fixed` 但只在有 `.git` 的树里成立** → 五层检测全跑在有 `.git` 的环境，包括 CI
2. **`unpushed` 测的是"领先 origin/main"** → 报 10，修 refspec 后报 0，**两次都"正确执行"**
3. **负例测试期待一个错误的 FAIL** → 测试成了错误断言的护城河（A-2）

### §5 Coverage and sensitivity: what the gate cannot see
- **覆盖矩阵**：逐列扰动，**13/26 不可见**
- 关键结果：力的检查阈值 ≈ 1e-5 相对（诚实）；但
  **运动学恒定偏移完全不可见**（标定偏置是工程数据最常见的错误）
- **敏感性分析**：P004 两条结论，一条余量 55–102 倍，**一条坐在自己边界上（1.7 倍即翻转）**
- **这一节是全文最有说服力的部分**：它量化了"验证通过"这句话的边界

### §6 Discussion / Limitations
**必须预先承认的四条**：

1. **n=1 项目**。但**分析单元是缺陷，不是项目**（n=26）。
   分类法的可迁移性需要他人检验——本文提供检验方法。
2. **零外部评审**。分类是作者自评，**无评分者间信度**。
3. **研究结论全部 `unresolved`**。本文**不能**声称基础设施改善了科研质量。
4. **文献相关工作缺失**（见 §7 硬阻塞）。

### §5.1 贡献三条（放回 §1）

1. **一个可复现的失效分类法**（7 类 26 条），附可重算的产物
2. **量化了"验证通过"的边界**（覆盖矩阵 + 阈值 + 敏感性）
3. **一个反直觉的发现**：**哈希冻结保证完整性，不保证正确性**；
   两者被混为一谈的方式，本身是一类系统性失效

## 7. 硬阻塞：文献获取

**本文必须有 related work**，而当前环境**搜索工具不可用**：

| 渠道 | 今日实测 |
|---|---|
| 内置搜索 | 连续多次空结果 |
| arXiv / Google Scholar | 超时 |
| ScienceDirect / MDPI / ResearchGate | HTTP 403 |
| Semantic Scholar | 202 空内容 |
| Bing | 返回词典页 |

**没有文献，就无法回答审稿人第一个问题："别人怎么做的？"**

**解决方式（按成本）**：
1. **用你新联系的业内教授**——请他推荐 3–5 篇必引，比搜索更准
2. 用大学图书馆 VPN（你若能访问）
3. 手工列出已知的四条（Sakana / VERID / 中国科大 2.2 / 自主实验室国标），
   逐篇通过可访问渠道取全文

**这不是写作问题，是可达性问题。必须先解决。**

## 9. 什么会杀死这篇论文

| 风险 | 后果 | 缓解 |
|---|---|---|
| **文献缺失** | 无法投 | §7，**最高优先级** |
| 审稿人说"这是自述，不是研究" | 拒 | 强调**可复现产物**：他们能重算 26 条分类 |
| 审稿人说"n=1" | 弱 | 分析单元是缺陷；并提供他人自审的方法 |
| 审稿人说"负结果无价值" | 拒 | 选接受负结果的 venue（F1000Research） |
| **写成了"忏悔录"** | 拒 | 必须有**分类法**和**量化**，不能只有叙事 |

---

## 10. 绝对不要写进论文的四句话

1. ❌ "我们的门禁保证了结果正确" → 只能写"保证了完整性 + 若干不变量"
2. ❌ "本方法可推广到任意领域" → 只能写"提供了可检验的分类法"
3. ❌ "实验证明有效" → 没有实验，只有 case study
4. ❌ "首次提出" → 未做充分文献检索前不得使用

## 11. 方法论声明

- **事实部分**：26 条缺陷、7 类分布、13/26 覆盖、阈值、三轮修复周期，
  全部来自仓库内产物，可核查。
- **判断部分**：venue 匹配度、两周排期、以及"这篇论文可投"本身，**均为判断**。
- **未做**：未检索文献（阻塞）；未做市场规模或影响力评估；
  未与任何潜在审稿人交流。
- **一个诚实的保留**：**这是一个单人 + AI 的项目，零外部评审。**
  若你是审稿人，你知道这条后会不会改变判断？
  **先自己回答这个问题，再决定投哪里。**
