# Ref-01B 初始浸没条件的显式化

> **本文档关闭 `CDFV-001_Reference_Configuration.md` §17.1 的 `Open` 项**
> "Initial immersion depth"。
>
> - 日期：2026-10-20
> - 相关：`T10`（CDFV 四参数）、`Ref-01B Completion Criteria`
> - 结论：**模型早已有确定取值（完全浸没）；过期的是文档，不是模型**

---

## 1. 现状核查：`Open` 是文档问题

`CDFV-001_Reference_Configuration.md` §17.1 记：

| 参数 | 值 | 状态 |
|---|---|---|
| Initial immersion depth | **Not selected** | Must not be inferred from rod length |
| Initial immersion | Not selected | **Open** |

**但代码里已有确定取值。** `baseline_model.py`：

```python
if z_start_m is None:
    z_start_m = -0.75 * cfg.length_m      # = -0.242250 m
```

而浸没长度定义为

```python
submerged_length(z) = clip(L/2 - z, 0, L)
```

实测产物（`Ref-01B-B-0p25mps.csv`）：

| | `z_center_m` | `submerged_length_m` | `immersion_fraction` | `buoyancy_N` |
|---|---:|---:|---:|---:|
| 首行 | −0.242250 | 0.323000 | **1.0000** | **20.151069** |
| 末行 | +0.242250 | 0.000000 | 0.0000 | 0.000000 |

`20.151069 N` 正是满浮力 `FULL_BUOYANCY_N`。**即：初始状态是完全浸没。**

**所以 `Open` 这个标记没有反映代码的实际行为。** 这本身就是一处应记录的缺陷：
文档与实现不一致，且不一致的方向是"文档说未定，代码已定"——
读者会以为还有自由选择，实际输出早已固定。

---

## 2. 模型注释也是错的

`baseline_model.py` L170–171 原写：

> "The default interval starts and ends **half a radius** beyond the fully
> submerged/fully emerged positions"

实测：`0.75L − L/2 = 0.25L = 0.080750 m`，而半径 `R = 0.045 m`，
即 **1.79 个半径**，不是半个。

**已更正为准确描述。**

---

## 3. 决策：保留 `z_start = −0.75 L`，并给出依据

### 3.1 采用的取值

| 量 | 值 |
|---|---|
| 初始中心位置 | `z_center = −0.75 L = −0.242250 m` |
| 初始浸没长度 | `h_sub = L = 0.323 m`（夹取到 `L`） |
| 初始浸没比 | **1.0（完全浸没）** |
| 初始浮力 | `20.151069 N`（满浮力） |
| 距"恰好全浸没"位置 | `0.25 L = 0.080750 m`（1.79 R） |
| 终止位置 | `z_center = +0.75 L`（完全出水） |
| 总行程 | `1.5 L = 0.4845 m` |

### 3.2 依据（诚实版）

**这是约定，不是测量。** P002 **没有**报告其浸没深度，且配置文档明令
"must not be inferred from the length of the connecting rod"。
所以在没有来源的前提下，任何取值都是约定。

**采用完全浸没的实质理由有两条：**

1. **它是无歧义的边界条件。** 出水问题的自然起点是"全浸没"，
   此时浮力取满浮力，无需另一个自由参数。
2. **在 Ref-01B 里，`z_start` 在 `z_start ≤ −L/2` 区间内不可区分。**
   见 §3.3——这是本文档最实质的技术理由。

### 3.3 关键性质：baseline 无法区分 `z_start ≤ −L/2` 的任何取值

Ref-01B 的基线**完全省略自由液面项**（`L-EXCLUDED-PHYSICS`），
故 `free_surface_force_N ≡ 0`。

于是浮力只通过 `submerged_length` 起作用：

```
z_start = −L/2       → h_sub = L（首行满浮力）
z_start = −0.75L     → h_sub = L（首行满浮力）
z_start = −3L        → h_sub = L（首行满浮力）
```

**三者首行完全相同。** 差别仅在于"保持满浮力状态的时长"。

**因此：在 baseline 范围内，`0.25L` 这个具体间隙是任意的，
不具有物理含义。** 这是比"某个半径数合适"更诚实的依据。

### 3.4 这个性质**不会**延续到 P003

**必须明确**：一旦 P003 加入自由液面项，`z_start` 就不再任意了——
它决定自由液面穿越的过程，而那正是 P003 的研究对象。

**所以本决策的适用范围是 Ref-01B 基线，不是整个 CDFV-001 研究。**
P003 阶段必须重新选择并给出独立依据（届时来源可能是 Ref-01S 实验数据）。

## 4. 对 `Ref-01B Completion Criteria` 的影响

完成条件要求："每个 benchmark 参数都有来源或**显式假设**"。

本决策把该项从"无状态"变为"**显式假设**"，故满足该条：

| 参数 | 来源 / 假设类型 | 记录位置 |
|---|---|---|
| 初始浸没 | **显式假设**（约定，非测量） | 本文档 §3 |
| 流体温度 | 仍 `Open` | §17.1 |
| 加速度剖面 | 仍 `Blocked — source required` | §17.1、`D002-002` |

**剩余 `Open` 项从 2 个减为 1 个（流体温度）。**
流体温度影响密度与粘度，但基线用 `A-FRESHWATER`（ρ=1000）且无粘性项，
故该项**在 baseline 内不影响任何已记录数值**——这一点应当写明，而不是留空。

---

## 5. 本决策没有做的事

1. **没有改 `z_start` 的取值。** 取值本身是合理的，不需要动。
2. **没有为 `0.25 L` 编造物理依据。** §3.3 说明它在 baseline 内不可区分，
   这比找一个"看起来有道理"的准则更准确。
3. **没有声称解决 P003。** §3.4 明确划出了本决策的边界。
4. **没有改流体温度项。** 它仍是 `Open`，只是补上了"为什么不影响基线"的说明。
