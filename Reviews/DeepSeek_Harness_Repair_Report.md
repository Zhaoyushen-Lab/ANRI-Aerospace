## Remaining Risks

1. **The gate is not yet approved.** The object is `in_review` with
   `review.status = revision_requested`. All claims remain "computationally
   consistent under author self-check" until a fresh independent review records
   an approving entry. Nothing in this repair changes that.
2. **The claim is algebraic, not physical.** It states that
   `constraint_force + buoyancy − weight = 0` within 1e-4 N for the emitted rows.
   It is not experimental validation, and the object now says so in the claim
   text, in `L-NO-EXPERIMENT` and in `L-EXCLUDED-PHYSICS`.
3. **Near-neutral configuration.** The fully submerged constraint force is
   ≈0.2436 N against a 19.9075 N weight (≈1.2 %). No uncertainty budget exists;
   this is recorded as open limitation `L-NEAR-NEUTRAL`. Any future change to
   mass, density, gravity or diameter moves the reported residual materially.
4. **Repository-wide LF conversion is a one-time large diff.** 81 files changed
   EOL only. Any collaborator with CRLF configurations will see those files as
   modified on their next checkout, and `.gitattributes` now uses `-text`, so
   accidental CRLF will show up as a real content change rather than being
   normalised away.
5. **CI has not been executed on GitHub.** The workflow logic is verified
   locally against an LF tree, but the hosted runner itself was not exercised
   from this machine.
6. **Two fault classes remain gate duties, not automated checks** (wrong
   velocity label in a CSV; an unsupported scientific conclusion). Both are
   documented in `Benchmarks/ANRI-RV-001/adversarial/README.md`.
7. **`verify_baseline.py` writes into the results directory it verifies.** The
   content is now deterministic, so this leaves the tree clean, but a verifier
   run against a directory it does not own would still create two files there.
   Bare-path invocation on a frozen directory is safe; the risk is limited to
   unfamiliar result directories.
8. **Local metadata still records host details.**
   `Models/CDFV-001/Ref-01B/results/local_run_meta.json` contains the UTC time,
   platform string and Python version. It is git-ignored and never hashed, so it
   cannot affect reproducibility, but it does exist on disk.
9. **`--dt` default is unchanged (0.001 s).** Anyone regenerating with a
   different `--dt` changes the CSV content and therefore every downstream
   hash; that is intended, but it means the frozen hashes are valid only for the
   documented command.
